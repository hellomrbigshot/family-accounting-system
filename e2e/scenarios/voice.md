# 语音记账 — VERIFY 步骤

AC 定义：[voice/SPEC.md](../../workflow/history/features/voice/SPEC.md)。

1. 使用当前授权 Key 对 Step Plan `/audio/asr/sse` 分别请求 2.5 ASR 与 3 ASR Max；用普通 `/v1` 区分权限和余额。不要仅凭 `/models` 返回列表判断可调用。2026-11-09 用户提供 Key：Step Plan 2.5 成功、3 Max 无权限；普通接口额度不足。
2. 用合成中文 WAV（16kHz/单声道/16bit）「今天买了一杯拿铁，花了十八块钱」验证真实 ASR 转写和字段解析。只使用合成候选或用户明确授权的标签，不读库后直接发送真实标签。
3. 提供合成标签「咖啡奶茶」「停车费」「高速费」：拿铁/星巴克应匹配咖啡奶茶；高速过路费不能误选停车费。
4. 用户授权正式列表后，可测试「茶百道消费10元」「库迪消费10元」是否返回奶茶咖啡，并将返回名称映射至原标签 ID。测试过期但未归档的旅游标签是否按消费日期生效。
5. 使用缺少 type/autoApply/archived 的旧文档样例，确认其作为普通未归档标签进入 prompt 和 ID 解析；不影响房间隔离及 archived:true 标签排除。
6. 登录后模拟麦克风和语音接口，检查表单标签展示；重录另一条语音应替换标签；打开标签选择器取消应生效。脚本：`pnpm test:e2e voice-tags`，无需真实麦克风或付费 API。
7. 检查模型因上限截断的响应（finish_reason=length）被拒绝，提示重试；复杂历史日期在 4096 上限时能输出完整 JSON。
8. 检查 iPhone 15 表单布局、控制台错误；截图位于 `e2e/artifacts/voice-tags*.png`。脚本不保存账单。

字段含义：type=normal/temporary；autoApply 仅控制有效期内的限时标签是否按日期自动添加，不禁止 AI 语义匹配；archived=true 禁止新支出自动选中。

2026-11-09 正式列表测试：用户明确授权的 8 个候选，9/9 通过。茶百道/库迪→奶茶咖啡；停车→停车费；高速过路费→空；北京/新疆有效期内饮品→旅游+奶茶咖啡；婚礼用品→备婚消费；赡养→赡养费；送礼→送礼。两句品牌消费用原 1024 token / 当天 4 个候选也通过。正式标签 ID 在本地库不存在，无法直接确认正式库底层字段；API 补默认值与原始 BSON 字段存在性须区分。
