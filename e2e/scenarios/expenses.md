# 支出 — VERIFY 步骤

> AC 定义：[workflow/history/features/expenses/SPEC.md](../../workflow/history/features/expenses/SPEC.md)  
> 测试映射：[TEST-CATALOG.md](../TEST-CATALOG.md) · expenses 段

## 场景

1. 打开 `/login` 并使用测试房间号、测试密码登录。
2. 进入「支出」页或直接打开 `/expenses`。
3. 期望看到「支出记录」、搜索框和统计徽章；如果存在支出数据，金额应带千位分隔符，且徽章格式为「总计: ¥xxx · N 笔」，N 等于当前可见列表条数。
4. 在搜索框输入任意能缩小结果的关键词，期望统计徽章中的笔数 N 随可见列表条数同步变化。
5. 点击新增支出入口，通常是页面上的浮动添加按钮。
6. 在新增表单中选择任意可用分类，填写金额 `12.34`，日期选择今天，备注填写 `E2E支出-<时间戳>`。
7. 保存后期望回到支出列表，并能看到刚创建的备注或金额。
8. 在搜索框输入刚创建备注中的 `E2E支出`，期望列表只展示匹配记录或至少包含刚创建记录。
9. 使用日期筛选选择今天作为开始和结束日期，期望刚创建记录仍然可见。
10. 直接打开 `/expenses?startDate=<今天>&endDate=<今天>`，期望日期范围预填或列表展示今天的记录。
11. 打开刚创建记录的编辑入口，将备注改为 `E2E支出编辑-<时间戳>` 并保存。
12. 期望列表展示修改后的备注。
13. 删除刚创建的记录并确认。
14. 期望列表中不再出现这条 `E2E支出编辑` 记录。
15. （Issue #3）有数据时期望列表挂载虚拟滚动容器（`data-testid="expense-virtual-list"`）；统计徽章在无搜索词时应反映服务端合计笔数。
16. （Issue #3）当筛选条件下记录数超过一页时，滚动列表到底部应追加加载下一页，全部加载完后出现「已显示全部」。

## 复杂交互提示

如果删除入口是左滑操作，请先使用页面快照定位支出条目，再执行滑动或点击可见的删除按钮。无法稳定自动完成左滑时，将删除步骤标记为 VERIFY 人工确认，并说明原因。

## 移动端滚动回归（AC-10 / AC-11）

1. 使用 iPhone 尺寸，在有超过 20 条数据的日期范围打开支出列表。
2. 滚动实际 `main` 容器，确认中间和末尾行正常出现；触底追加直至最后一条与「已显示全部」。
3. 回到顶部，确认首条重新出现，底部导航始终在视口内。
4. 分别在 320×568、740×360 尺寸重复上述操作。
5. 搜索已有记录，再清空关键词，确认匹配列表及重新查询后的多页列表都可滚到末条。
6. 检查浏览器错误；分页接口应按页递增，不重复请求同一页。

## 大数据动态行高回归（AC-12）

1. 使用独立临时房间，通过真实支出 API 准备 2,003 条记录，金额各 12.50，日期在查询范围内，长短备注交替。
2. 通过真实登录页登录该房间，393×852、320×568 下分别从首屏连续滚动到末条。
3. 监听实际 XHR 响应：页码必须 1–101 连续且不重复；汇总 2,003 个唯一 ID，总额 25,037.50；末页 3 条且 hasMore=false。
4. 检查滚动途中无可见区域空白、少量 DOM 行、返回顶部首条、底部导航可见；监听 window error / unhandledrejection，不忽略 ResizeObserver 错误。
5. 横屏 740×360 查看末条；搜索匹配全部数据，依次跳转 0/25/50/75/100% 位置；清空搜索恢复第 1 页。
6. finally 清理该临时房间及其全部支出，禁止修改现有账目。
